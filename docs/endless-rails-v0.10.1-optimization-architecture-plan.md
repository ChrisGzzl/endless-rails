# Endless Rails v0.10.1 优化与架构问题修复建议

版本：v0.10.1\
目标：在完成「列车 Build + 永久
Research」第一版后，进行架构稳定化和系统边界整理，为后续 v0.11
内容扩展提供基础。

------------------------------------------------------------------------

## 一、总体判断

v0.10.1 已经完成了从「局外成长原型」到「完整 Meta 系统」的第一步：

-   列车 Build 系统
-   五分支天赋
-   永久 Research
-   buildStats 单局属性生成
-   存档迁移
-   DOM + Canvas 双呈现

当前主要问题不是功能缺失，而是：

1.  Meta 系统职责开始集中；
2.  Build / Research 边界需要进一步明确；
3.  单局属性生成链路需要固定；
4.  为未来 Boss、地图、挑战模式预留扩展接口。

因此 v0.10.1 后续建议以「架构整理 + 系统稳定」为主，不急于增加新玩法。

------------------------------------------------------------------------

# 1. Meta 架构拆分

## 当前问题

目前 `src/meta/longterm.js` 承担过多职责：

-   玩家永久数据
-   列车等级
-   天赋树
-   Research
-   Blueprint
-   Region
-   Save
-   Migration
-   buildStats

当前规模尚可维护，但随着未来加入：

-   更多车厢
-   装备
-   Boss 词缀
-   活动系统

会再次形成大型核心文件。

------------------------------------------------------------------------

## 建议目标结构

    src/meta/

    ├── index.js
    │   Meta 系统入口

    ├── profile/
    │   玩家永久数据

    ├── train/
    │   ├── defs.js
    │   ├── talents.js
    │   ├── build.js
    │   └── stats.js

    ├── research/
    │   ├── defs.js
    │   ├── levels.js
    │   └── calculator.js

    ├── blueprint/
    │   blueprint.js

    ├── region/
    │   region.js

    ├── migration/
    │   v09-v010.js

    └── save/
        storage.js

------------------------------------------------------------------------

## 拆分原则

`longterm.js` 不再负责业务计算。

只负责：

-   加载
-   保存
-   提供 Meta 状态

例如：

``` js
meta.train
meta.research
meta.resources
meta.blueprints
```

计算交给独立模块。

------------------------------------------------------------------------

# 2. 固化 buildStats 数据流

## 当前方向

v0.10.1 已采用：

永久成长 → Build → buildStats → 单局

这个方向正确，需要继续强化。

------------------------------------------------------------------------

## 推荐数据流

    永久数据

        ↓

    Meta Profile

        ↓

    Train Build

        ↓

    Research Modifier

        ↓

    Blueprint Modifier

        ↓

    RUN CONFIG

        ↓

    buildStats

        ↓

    Combat / Simulation

------------------------------------------------------------------------

## 规则

进入游戏后：

所有战斗系统只能读取：

``` js
run.buildStats
```

禁止：

``` js
research.level
talent.level
blueprint.active
```

直接参与战斗计算。

------------------------------------------------------------------------

## 好处

未来增加：

-   Boss 强化
-   地图效果
-   挑战模式
-   天气
-   随机事件

只需要：

    Modifier
        ↓
    buildStats
        ↓
    Run

无需修改 Combat。

------------------------------------------------------------------------

# 3. Build 与 Research 边界整理

## 当前风险

两个系统都有：

-   攻击提升
-   防御提升
-   修复提升

容易导致玩家理解困难。

------------------------------------------------------------------------

# Research 定位

## 永久成长

特点：

-   稳定
-   永久
-   无选择

例如：

无人机研究：

    Lv1
    基础攻击 +3%

    Lv10
    攻击间隔降低

    Lv20
    技能倍率提升

    Lv30
    突破强化

Research 负责：

「账号越来越强」。

------------------------------------------------------------------------

# Build 定位

## 每局策略

特点：

-   有选择
-   有取舍
-   改变玩法

例如：

无人机扩容：

    无人机数量 +2

    但是：

    单体伤害 -15%

高速列车：

    移动速度 +20%

    但是：

    列车耐久下降

Build 负责：

「这局怎么玩」。

------------------------------------------------------------------------
